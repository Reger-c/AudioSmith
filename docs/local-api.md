# AudioSmith Local API and MCP

*M5 (thread #20); the app's modules, thread #35. Code: [`internal/api`](../internal/api) (HTTP server, OpenAI-compatible and native routes, auth, OpenAPI), [`internal/mcp`](../internal/mcp) (MCP server and stdio shim), `api*.go`, `integrations*.go`, `tools*.go` (the app's side).*

While AudioSmith runs, it serves an HTTP API on **`http://127.0.0.1:3901`** (Settings → Local API: on/off, port). It is a second client of the app's services and job queue: requests run at interactive priority next to the Studio's, the licence gate applies, takes land in the History and transcripts on the Transcribe page.

| Path | What |
|---|---|
| `/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/audio/translations`, `/v1/models`, `/v1/audio/voices` | OpenAI's audio API |
| `/api/…` | AudioSmith's own: voices (list, clone from an upload, design, delete, audio), `generate` (the full recipe, any length), takes, transcripts, jobs (+ SSE, long poll), models (+ download), languages, tools (probe, direction, rate fit); and the app's modules (below): the project library, Stories and Audiobook, dubbing and batch, Discover voices, take and transcript exports, workflows |
| `/ws/tts` | streaming speech over a WebSocket |
| `/mcp` | the MCP server (Streamable HTTP) |
| `/health`, `/.well-known/audiosmith-speech` | readiness; capabilities for discovery |
| `/openapi.json`, `/docs` | the OpenAPI 3.1 description (hand-written, `internal/api/openapi.json`; `TestOpenAPIMatchesRoutes` keeps it equal to the routes) and the bundled RapiDoc viewer (also Settings → Local API → Open the reference) |

**Source code (AGPL-3.0).** AudioSmith is licensed under the GNU AGPL version 3, whose section 13 asks a program that users reach over a network to offer them its source. `/`, `/health` and `/.well-known/audiosmith-speech` carry `"source_url": "https://github.com/hehehai/AudioSmith"` and `"license": "AGPL-3.0-only"` (SPDX), the spec's `info.license` says the same, and Settings → Diagnostics and about shows both (`internal/api/health.go`). Someone who changes AudioSmith and lets others use it over the network (LAN sharing, for instance) should point `api.SourceURL` at their own source.

## OpenAI compatibility

Point any OpenAI SDK at `base_url="http://127.0.0.1:3901/v1"` with any `api_key` (it is ignored on this Mac unless a key is required).

**Model names** (thread #45). Every model keeps its technical `id`, `repo` and `label` ("Qwen3-TTS 0.6B CustomVoice"); `GET /api/models`, `GET /v1/models` (in `audiosmith`) and MCP `list_models` add `display_name` (the friendly name in English: "Standard voices"), `ui_name` (the name the app shows, in its UI language: "标准音色" — the one the user knows; agents should say it and pass the `id`), and in `/api/models` and MCP `description` (one line) and `tags` (`chinese`, `english`, `multilingual`, `clone`, `design`, `voices`, `fast`, `quality`, `light`, `non-commercial`).

**Speech.** `model`: `tts-1`, `tts-1-hd`, `gpt-4o-mini-tts` (any `gpt-*-tts`) are the Studio's default model; for a saved voice that model cannot speak (a clone on Kokoro), the voice's own model or the first downloaded one that can. A catalogue id, repo, label or friendly name (`display_name`, or `ui_name` in the app's language) picks a model. `voice`: a saved voice's id or name (case-insensitive; two of a name → 409 `ambiguous_voice`), a built-in speaker of the model, `default`, or one of OpenAI's names (alloy, ash, ballad, coral, echo, fable, nova, onyx, sage, shimmer, verse, marin, cedar), which pick a built-in speaker of that voice's gender. `instructions`: the delivery on instruct models (Qwen3-TTS CustomVoice gets `"Speaker, instruction"`), the voice to design on design models without a saved voice (Qwen3-TTS VoiceDesign, OmniVoice), a style hint on clones; models that take none ignore it (`X-AudioSmith-Ignored`). `input` ≤ 4096 characters (`/api/generate` takes 100,000). `speed` 0.25–4. Extensions: `language`, `seed`, `duration`, `steps`/`num_step`, `temperature`, `top_p`, `guidance_scale`, `normalize` (`exaggeration` is accepted but no model takes it any more: it is reported in `X-AudioSmith-Ignored`). Parameters a request leaves out get the model's recommended values (from the model evaluation, `internal/catalog/presets.json`), as the app's pages do: Qwen3-TTS `temperature` 0.7 and `top_p` 0.8 (the models' own 0.9 / 1.0 measured worse), OmniVoice `guidance_scale` 1.5 and 32 `steps`; Chatterbox Turbo `temperature` 0.8 (its own); models without a preset use their own defaults. Values you send are used as sent. **Removed models** (thread #43: `kitten-tts-mini-0.8`, `moss-tts-nano-100m`, `chatterbox-8bit`, `marvis-tts-250m-v0.2-8bit`, `soprano-80m-bf16`, `pocket-tts`; by id, repo or label) are no longer listed, but a request that names one is answered by its replacement — Kokoro, Qwen3-TTS 0.6B Base for MOSS-TTS-Nano, Chatterbox Turbo for Chatterbox, and Chatterbox Turbo for a cloning request to Marvis, Soprano or Pocket TTS — with the headers `X-AudioSmith-Replaced-By` (the model used) and `X-AudioSmith-Warning`, and `replaced_by` / `warning` in JSON answers (`/api/generate`, the WebSocket's `start`, MCP `generate_speech`). When the replacement can't do what was asked (a built-in speaker only the old model had) the answer is 400 `model_removed`; `POST /api/models/{id}/download` of one is 410 `model_removed`. `GET /v1/models/{id}` (and `/api/models/{id}`) of a removed model answers `{"id","object":"model","label","repo","removed":true,"replaced_by","clone_replaced_by","warning"}`.

| `response_format` | Answer |
|---|---|
| `wav` (the default here: OpenAI's default, mp3, needs the optional ffmpeg) | 16-bit WAV at the model's rate; **streamed as the take is made** (a sentence or so at a time; the header says "length unknown") |
| `pcm` | 24 kHz 16-bit mono little-endian, streamed the same way (resampled when the model's rate differs) |
| `aac` / `m4a` | AAC-LC in an M4A container through the engine's `media.encode`, once the take is made |
| `mp3`, `opus`, `flac` | with ffmpeg set up (Settings → Audio tools): MP3 192 kb/s, Ogg Opus 96 kb/s, FLAC, once the take is made; without it 400 `unsupported_format` |

`stream_format: "sse"` sends `speech.audio.delta` events (base64 of the format's bytes) and `speech.audio.done` with `usage`. `normalize: true` (Even out volume) needs the whole take, so it is sent when done. Response headers: `X-AudioSmith-Take-Id`, `-Job-Id`, `-Model`, `-Voice`, `-Ignored`, `-Seed` (not on live streams). Streamed audio equals the saved take: API takes are not mastered unless `normalize` is on.

**Transcriptions.** Multipart `file` (any audio or video AVFoundation reads, ≤ 1 GiB), `model` (`whisper-1`, `gpt-4o-transcribe` → Transcribe's Accurate model; `gpt-4o-mini-transcribe` → its Fast model; or a catalogue model), `language`, `prompt`, `response_format` (`json`, `text`, `verbose_json`, `diarized_json`, `srt`, `vtt`), `timestamp_granularities[]` (`word` runs the forced aligner when the model has no word times). **Speakers** (thread #48): `speakers=true` (AudioSmith's extension), `model=gpt-4o-transcribe-diarize` or `moss-transcribe-diarize-8bit`, or `response_format=diarized_json` transcribe with the speakers model (MOSS-Transcribe-Diarize 0.9B, 8-bit, Apache-2.0; slower than the default, about 5× real time; it must be downloaded): segments carry `speaker` (`S1`, `S2`… in order of appearance, or the name given on the Transcribe page) in `verbose_json` and `diarized_json` (OpenAI's shape: `segments[].type` `transcript.text.segment`, `speaker`), and SRT cues start with it. Audio over 10 minutes goes in 10-minute windows that overlap by 60 s, linked by who speaks in the overlap; windows without speech are skipped. `prompt` becomes its hotword hint. Not with translations (400). `POST /api/transcripts` takes `speakers=true` too (the transcript's `segments[].speaker`, and `speakers` with the names given), and MCP `transcribe` `speakers: true` (segments with `speaker` and `speaker_name`; `text` as one `S1: …` paragraph per turn). `stream=true` → 400. The transcript is kept on the Transcribe page (title "<file> (API)"). Unless Settings → Transcribe names one, the default model follows `language`: `qwen3-asr-0.6b-4bit` (Qwen3-ASR: Chinese, English and 28 more, and detection) or, for a language it does not know, `whisper-large-v3-turbo-4bit` (Whisper). A `prompt` is not sent to Qwen3-ASR with audio longer than 30 s (it copied the vocabulary into the text); a hallucinated " The." at the end of a long Qwen3-ASR transcript is dropped; word times of audio longer than 4½ minutes are aligned in windows of at most 4 minutes. **Removed** (thread #46): `parakeet-tdt-0.6b-v3` is answered by the default for the language, with `X-AudioSmith-Replaced-By` / `X-AudioSmith-Warning` (`replaced_by` / `warning` in `POST /api/transcripts` and MCP `transcribe`); the language models `gemma-4-e4b-it-4bit`, `gemma-4-e2b-it-4bit`, `qwen3-1.7b-4bit` (→ `qwen3-4b-instruct-2507-4bit`) and `mel-roformer-kim-vocal-2` (→ `htdemucs`) are not listed, `GET /api/models/{id}` describes them, and their download is 410 `model_removed`.

**Translations** (speech → English): the transcript is translated by Settings → Writing help's language model (no catalogue model translates speech yet); without one, 501 `translation_unavailable`. English speech comes back as transcribed.

**Errors** use OpenAI's shape, `{"error":{"message","type","param","code"}}`, plus data: 403 `licence_required` (with `model`, `licence`, `licenceName`, `licenceURL`), 409 `model_not_downloaded`, 404 `model_not_found`, 400 `voice_not_found` / `unsupported_format` / `unsupported_model` / `needs_reference` (a model that only clones voices, without `ref_audio` or a saved cloned voice; `GET /v1/models` marks such models `"needs_reference": true`; no listed model is one today) / `model_removed` (see Speech), 503 `engine_unavailable` (engine down or restarting) and `queue_timeout` (waited > 120 s behind other work; Settings `api.queueSeconds`), both with `Retry-After`. A client that disconnects cancels its job.

## Native API notes

- `POST /api/generate` waits for the take and answers it (`wait: false` → 202 with the job, its SSE `events_url` and the take's `audio_url`). Even out volume is on by default, as in the Studio.
- `GET /api/jobs/{id}/events`: SSE `job` events (the job, at once and at each change), then `done`. `GET /api/jobs/events`: every job. `GET /api/jobs/{id}?wait=N` long-polls (≤ 60 s): it answers when the job ends or the time is up. Jobs carry `done` and `files` (absolute paths of what they made).
- `POST /api/voices` (multipart `file`, `name`, `ref_text`, `language`, `style`) clones; `POST /api/voices/design` (`description`, `name`, `language`, `seed`, `model`) designs; both save to the voice library.
- `/ws/tts`: send `{"text":…, "voice":…, …}` (the fields of `/api/generate`, plus `sample_rate`: 24000 by default, 0 for the model's); receive `{"type":"start",…}`, binary PCM16 frames, `{"type":"done","ttfa_ms","rtf",…}`; `{"type":"cancel"}` stops; one request at a time per socket.

## The app's modules (thread #35)

The Local API and MCP drive AudioSmith's pages through the same services the UI uses (`api.Studio`, implemented by `apiBackend` in `api_studio*.go`; REST in `internal/api/studio_http.go`, shared checks in `studio_ops.go`, MCP tools in `internal/mcp/studio.go`). What stays in the app: settings, model downloads and licences, phone calls (Twilio), dictation, editing workflows' steps, watch folders, the dub timeline, voice editing and microphone recording.

| Area | REST | MCP |
|---|---|---|
| Project library | `GET /api/projects?category=&search=` | `list_projects` |
| History | `GET /api/takes` (existing), `POST /api/takes/{id}/export` | `list_takes`, `export_audio` |
| Audiobook | `POST /api/audiobooks` (path of an EPUB/TXT/MD/DOCX, or text) | `create_audiobook` |
| Stories | `POST /api/stories` (a script "Name: line", a file, or lines) | `create_story` |
| Both | `GET`/`PATCH`/`DELETE /api/longform/{id}`, `POST /api/longform/{id}/render`, `POST /api/longform/{id}/export` | `get_longform`, `update_longform`, `render_longform`, `export_longform`, `delete_item` |
| Dubbing | `POST /api/dubs`, `GET`/`PATCH`/`DELETE /api/dubs/{id}`, `POST /api/dubs/{id}/run`, `POST /api/dubs/{id}/export` | `create_dub`, `get_dub`, `edit_dub`, `run_dub`, `export_dub`, `delete_item` |
| Batch | `GET /api/batch`, `POST /api/batch` | `list_batch`, `batch_dub` |

| Jobs | `GET /api/jobs/{id}?wait=N`, `POST /api/jobs/{id}/cancel`, `GET /api/jobs/{id}/events` | `get_job` (`wait_seconds` ≤ 60), `cancel_job` |

- **One async pattern.** Renders, dub runs, batch dubs, dub exports and workflow runs return a job id at once (REST 202 with `job_id`, `job_url`, `events_url`). The id is a queue job's, or a **group** named by its jobs' owner: `longform:<render id>`, `dub:<dub id>`, `workflow:<workflow id>`. Every job endpoint answers both: a group's `state`, `progress` (stage, fraction), `error` (code, message), `result` (the render's chapters and book, the dub's tracks, the workflow's items) and `files` (absolute paths). Cancelling a group stops it as the page's Stop does (what was made is kept; running again goes on from there). The jobs show in the app's job list.
- **Same as the pages.** Projects are saved in the library (`Library.SaveDoc`) and open on their pages (an open page without changes of its own shows the new version); renders are the longform service's (one full render at a time: 409 `busy`); dubs are made with Settings → Dubbing's choices (`newDubProject`; with no target in the call or the settings a dub is made in Chinese, `dub.DefaultTarget`, and switched to English once the video turns out to be Chinese, `dub.Project.AutoRetarget`; the Batch page's default does the same), translation follows the user's translator (no translator: `dub.no_translator`); batch dubs use the Batch page's settings, overridden for that call only (nothing is saved); workflows run with one-off inputs when the call gives scripts or files (`services.RunOptions.Inputs`: the saved workflow and the results of its own inputs stay); Discover voices searches with the page's query (`galleryFilterQuery`) and "Use voice" saves the same designed voice (`archetypeVoice`, once); take exports fill the Export audio dialog's form (`exportForm`: format, bits or bitrate, rate, channels, loudness, trim, tags, script and subtitles) from the kind's first-use defaults; book exports are Save's (`writeRenderFile`, `writeRenderChapters`, `bookEncodeOptions`). Exports are recorded in Projects → Exports.
- **Paths.** Inputs are absolute paths of readable files (`~/` works; `invalid_request`, 404 `not_found`). Outputs go to the agents' folder (Settings → Local API's MCP folder) or an absolute `directory` the call names (made if missing); `filename` is a name only. These routes are for this Mac (or the key); the MCP tools refuse LAN clients with the PIN only (`unauthorized`).
- **Stories' performance.** `update_longform` (`PATCH /api/longform/{id}`) takes `scene`, `personas` (character → persona), `emotions` (line id → `steady`, `happy`, `excited`, `tender`, `pleading`, `hesitant`, `worried`, `hurt`, `sad`, `angry`, `scared`, `surprised` or `apologetic`; `""` clears), `intensities` (line id → 0–3 with an emotion, 1–3 with a direction), `directions` (line id → your own wording), `pacing` (`dialogue`, `reading`, `relaxed`, `fixed`), `merge_turns`, `even_out_voices` and `dialogue` (true: the characters' lines on the dialogue model, a scene at a time; refused below its memory or outside Chinese and English); emotions, intensities and directions set this way are kept when the director runs again. `direct: "fill" | "all"` runs the AI director (the `direction_parse` writing-help route; 400 `llm_unavailable` without a language model, 502 `director_failed` when it fails) before saving: it plans the story's emotions — a baseline per character, and per line an emotion, an intensity and whether it is a turn, mostly steady — and rules keep them continuous. `get_longform` returns `scene`, `pacing`, `dialogue`, `continuity` (`instruct`, `intensity` or `lines`), each cast member's `persona` and each line's `emotion`/`intensity`/`turn`/`direction`.
- **Deleting** needs a confirmation: MCP `delete_item` with `confirm: true` (kind take, voice, transcript, project, dub), REST `DELETE /api/longform/{id}?confirm=true` and `/api/dubs/{id}?confirm=true`; without it 400 `confirm_required`. The older `DELETE /api/takes|voices|transcripts/{id}` accept `?confirm=true` but do not require it (compatibility).
- **Errors** keep the API's codes: `invalid_request`, `not_found`, `model_not_found`, `voice_not_found`, `ambiguous_voice`, `unsupported_model`, `unsupported_format`, `needs_reference`, `licence_required`, `model_not_downloaded`, `engine_unavailable`, `busy`, `not_ready` (a step must come first), `not_renderable` (blocking problems, listed in `problems`), `confirm_required`, `unsupported` (a backend without the modules); a failed job's error carries the stage's code (`dub.no_translator`, `workflow.invalid`…).

## Security

| Check | Rule |
|---|---|
| Bind | 127.0.0.1 only. LAN sharing opens a second listener on all interfaces (port + 1 by default) |
| Host (DNS rebinding) | loopback names only (127.0.0.1, localhost, ::1); on the LAN listener also the Mac's private IPs and host name |
| Origin | absent (not a browser), the API's own (the `/docs` page), or listed in Settings → Local API; preflights answered only for those |
| CSRF | state-changing `/api` requests need `X-AudioSmith-Request: 1` or the key |
| Key | optional on loopback (a Bearer sent anyway is ignored: SDKs always send one); **Require the key on this Mac too** makes it mandatory except `/health`, discovery and the reference. The key lives in the Keychain (`AudioSmith` / `api.key`); Settings shows a new key once |
| LAN | the 6-digit PIN (`X-AudioSmith-Pin`, `?pin=`, or cookie `audiosmith_pin`; new each time sharing starts, never saved) covers speech, transcription, reading voices and models, MCP; everything else needs the key; 10 wrong PINs or keys a minute → 429 |
| Files | MCP tools read paths only for clients on this Mac (or with the key); LAN clients send base64. Tools write only to the MCP folder (Settings → Local API; default `<data>/mcp`) |

## MCP

Streamable HTTP at `/mcp` (official Go SDK, stateful sessions). Tools: `generate_speech`, `clone_voice` (needs `consent: true`), `design_voice`, `describe_voice`, `transcribe`, `list_voices`, `list_models`, `list_languages`, `check_health`, and the modules' 24 (above; `mcp.StudioTools`). Resources: `voice://{id}`, `history://recent`. Audio comes back inline (`audio/wav` content), as a file in the MCP folder, or both (Settings, or the call's `output`). Each agent may have its own voice: Settings → Local API → Each agent's voice, keyed by `X-AudioSmith-Client` or the client's MCP name.

**stdio:** `AudioSmith.app/Contents/MacOS/AudioSmith --mcp-stdio [--client <name>]` relays a stdio client to the running app, found through `~/Library/Application Support/AudioSmith/api.json` (written while the API runs). `AUDIOSMITH_API_KEY`, `AUDIOSMITH_CLIENT`, `AUDIOSMITH_API_URL` override. If the app is not running, requests get an error that says so; if it restarts, the shim opens a new session by itself.

The Integrations page (sidebar → Utilities) generates setups for Claude Code, Cursor, Codex CLI, generic MCP, the OpenAI SDK (curl, Python, JavaScript), the OpenAI Agents SDK and n8n, for the current port. They never contain the key unless the user asks; with "Require the key" on they read `AUDIOSMITH_API_KEY`.

The pages of Claude Code, Codex CLI, Cursor and generic MCP open with an **agent setup prompt** (`integrations_prompt.go`, thread #33): a text in the UI's language, made from the live settings (port, key, saved voices, the agents' folder), that the user copies (or saves as .txt) and pastes into the agent. It tells the agent to check `/health`, add the `audiosmith` server to its user-level configuration (Claude Code `claude mcp add --scope user`, Codex `~/.codex/config.toml` with `tool_timeout_sec = 600`, Cursor `~/.cursor/mcp.json`; back up and merge, idempotent), verify with its own listing and a curl MCP handshake (initialize → tools/list → `list_voices`), install the agent skill (below), and report. With "Require the key" the agent reads the key from the Keychain (`security find-generic-password -s AudioSmith -a api.key -w`) and keeps it out of shared files; the key is in the text only when the user turned on "Put my API key in the setups". `TestAgentPromptHandshake` runs the prompt's commands with curl (bash and zsh) against the real server. The manual blocks fold under Manual setup.

**Agent skill** (`integrations_skill*.go`, threads #34 and #35). MCP gives a new chat only bare tool names, so each agent page also makes a skill in the [Agent Skills](https://agentskills.io) format, in the UI's language: a folder `audiosmith/` with `SKILL.md` and `reference/tools.md`. SKILL.md says what AudioSmith is and when to use it (the frontmatter `description`), how to check `/health` and what to do when the app is down, the error codes, **what AudioSmith does** (every page of the sidebar by the name the user sees, plus Settings and Dictation: what it is for and the tools that do it, or where it stays in the app; `TestAgentSkill` checks that no page is missing), the long-job pattern, every tool in a line, recipes (narrate a README section, a voice-over, a meeting to SRT, find a voice, an EPUB to an M4B, a two-speaker story, dub a video into English with subtitles, batch-dub a folder, narrate with a Discover voice, export at podcast loudness, run a workflow, follow and cancel a job), manners (consent before cloning, confirmation before deleting, long jobs with `wait_seconds`, no settings or downloads, calls and dictation are the user's, 127.0.0.1 only, report file paths), and a curl fallback. `reference/tools.md` has every tool with all its arguments (`TestAgentSkill` compares them with the server's schemas). It carries the live port, client, saved voices, the agent's own voice and the agents' folder, never the key. User-level locations: Claude Code `~/.claude/skills/audiosmith/SKILL.md` ([docs](https://code.claude.com/docs/en/skills)), Codex `~/.agents/skills/audiosmith/SKILL.md` ([docs](https://developers.openai.com/codex/skills)), Cursor `~/.cursor/skills/audiosmith/SKILL.md` ([docs](https://cursor.com/docs/skills); Cursor also reads `~/.claude/skills` and `~/.agents/skills`); other agents `~/.agents/skills` or their instructions file. The running app serves the same files at `GET /api/agent-skill?agent=<claude-code|codex|cursor|mcp>&file=<SKILL.md|reference/tools.md>` (text/markdown, this Mac or the key; never the key in it), and the setup prompt's step 4 (prompt ≤ 8 KB) installs the folder with a bash/zsh script that `curl`s each file to `.new`, backs up a different file, then moves it (idempotent; if the app does not answer it changes nothing and the prompt sends the user to Install skill… or Save skill…; `TestAgentSkillScript` runs it with a temporary HOME in bash and zsh against the real API server); the page's **Install skill…** (after a confirmation) does the same, **Save skill…** saves `audiosmith-skill.zip` (the folder, as claude.ai and Claude Desktop upload skills), **Copy skill** copies both files as one text, and the card says when the installed copy is out of date. The MCP server's `initialize` also returns compact `instructions` (`mcp.Instructions`) for agents without the skill, and `list_models` marks `needs_reference` models.

## Tools page

A/B voices (previews, not kept), Convert (transcribe a recording, speak it in a saved voice; "Match the recording's length" uses OmniVoice's target duration, else time-stretches the take with `dsp/stretch` — the matched take joins the History), Rate fit (`translate.Fitter`), Direction (`translate.Director`, with a spoken sample on Qwen3-TTS CustomVoice), File probe (`media.probe`).
